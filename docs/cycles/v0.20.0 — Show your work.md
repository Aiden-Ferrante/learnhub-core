## Problem

The extraction gate does not check the thing its name implies.

`LEARN_REQUIRE_SOURCE` (`concepts_extract.py:177`) drops a concept whose `source_sentence` is
**empty**. It never checks that the sentence is *real*. A model that invents a
plausible-sounding quote passes cleanly — which is the exact shape of every bug this codebase
has spent three cycles fixing: a value that looks right and is never compared against the
thing it claims to describe.

So the honest statement before this cycle was not "extraction is grounded". It was **"nobody
has ever checked"**, over 1,463 concepts across 14 books, one of which is being studied.

### What the measurement actually said

Run 2026-08-25 against the live database, every stored concept compared to the markdown of
its own section:

| verdict | n | |
|---|---|---|
| verbatim | 1,265 | 86.5% |
| partial (a full sentence of a multi-sentence quote) | 64 | 4.4% |
| near-verbatim (long run survives, string does not match) | 117 | 8.0% |
| paraphrase (all words present, rewritten) | 17 | 1.2% |
| **invented** | **0** | **0%** |
| **misattributed to another section** | **0** | **0%** |

**Grounding holds. 1,463 of 1,463 trace to their own section.** The falsifier above did not
fire, and the gate — crude as it is — is doing its job.

That is a genuinely good result and it must not be overclaimed. Two things it does not say:

1. It says the *quote* is real. It says nothing about whether the **signal** — the 1–3
   sentence explanation the learner actually reads — follows from that quote. A real sentence
   with a wrong gloss attached passes every check above.
2. It was verified mechanically. The waypoint asks for a chapter **read** against the source,
   and normalized string matching is a proxy for that, not the thing. The node's sounding is
   set to `proxy` accordingly, not `observed`.

### The finding that did surface

The 134 non-verbatim rows are **not a grounding problem, they are an encoding problem** —
and tracing it corrected the first guess in this record, which is worth leaving visible.

**It is not conversion damage, and it is not in the reader.** `raw_content` holds **zero**
byte escapes and zero broken macros; the stored book text is clean, and
`normalize_math_in_markdown` preserves `\text{}` under both profiles. The damage is confined
to `ext_concepts` — what the *model* wrote down, not what the *converter* produced.

Two mechanisms, found by reproducing them:

1. **JSON eats the backslash, and `_norm_part` eats the evidence.** Generation is
   grammar-constrained (`gateways/llm.py` sets Ollama's `format` to the schema), so the model
   must emit syntactically valid JSON — and `\t` *is* valid JSON. A model copying
   `$P(a \text{ and } b)$` emits `\text`, `json.loads` decodes `\t` to a TAB exactly as the
   spec requires, and `\text{` becomes TAB + `ext{`. Then `_norm_part`'s `\s+ → " "` collapses
   the tab to a space and the last trace is gone. Stored: `$P(a ext{ and } b)$`. Nothing
   raises, nothing is malformed, and the grammar cannot help — it has no way to know the
   model meant a backslash.
2. **Byte-fallback tokens leak as literal text.** A character the model knows only as
   byte-fallback tokens detokenises to the literal string `<0xE2><0x84><0x92>` instead of `ℒ`.

The second one *was* user-visible, in the half I initially got right for the wrong reason:
`signal` is rendered on concept cards, so mojibake sat on screen — but as the model's
explanation, never as the book's own words.

## Appetite

One sub-cycle, and it is deliberately small because the alarming version of this problem
turned out not to exist. If it grows into "improve extraction quality", that is a different
cycle with a different waypoint — abort and re-plan rather than expanding.

## Plan

**1. Land the verifier.** `scripts/check_grounding.py` already exists and reproduces the
table above; it classifies rather than passing/failing, because "how did it fail" is the
useful answer. Exit non-zero only on `invented` / `elsewhere` / `ungated` — encoding damage
is a Conversion finding and must not turn this check red, or the signal is lost inside a
failure nobody can act on.

**2. Wire it where it will be seen.** A check that runs when someone remembers is the same
silence as no check (`docs/testing.md` makes this argument about the test tiers). The wiring
has to answer an awkward question first: **CI has no concepts.** Its Postgres is seeded from
the schema and holds an empty `ext_concepts`, so running the script there would go green
forever while proving nothing — the exact failure this cycle exists to remove, reproduced in
the fix for it. So the check splits: CI seeds its own corpus and proves the checker can
fail; the script runs against a real library and is the only one that can tell you something
new.

**3. Fix the encoding damage** at the parse boundary — `repair_model_text` in
`concepts_extract`, applied *before* `_norm_part` collapses the evidence. Byte-fallback runs
decode unconditionally (`<0xNN>` is never real prose). Backslash restoration is a guess, so
it is checked against the section's own markdown and kept only when it makes the quote
findable — the rule the rest of this file lives by. Only t/b/f are repaired without ground
truth; n/r collide with `\not`/`\nabla`/`\rho` but also with an ordinary wrapped line, so
they are tried only when the section text can confirm them.

**3b. Backfill.** The fix protects new extractions and does nothing for rows already stored,
and re-extraction is hours of model time per book to recover text that is recoverable
arithmetically. `scripts/repair_concept_sources.py`, dry-run by default.

**4. Re-run and record.** The near-verbatim bucket should collapse toward zero once the
encoding is fixed; whatever remains is real paraphrase and is a prompt question, not a
pipeline one.

**Non-goals.** No change to the extraction prompt. No LLM-based grounding judge — that
replaces an unchecked claim with an unchecked checker, and the whole point is a check you can
run yourself. No signal-vs-source verification: that is the *next* question here and it needs
its own waypoint, not a bolt-on to this one.

## Exit criteria

1. `check_grounding.py` runs against the live database and reports the classification table.
2. It runs somewhere automatic, and a regression is visible without anyone remembering to
   look — where "runs" means *can fail*, demonstrated, not merely *is invoked*.
3. No stored concept carries a byte-escaped character, and a `\text{}` in a quoted sentence
   survives extraction — verified on a **concept card in the running app**, not only in the
   database. (Written originally as a claim about conversion and the reader; the tracing in
   Problem showed the book text was never damaged, so this is what there is to check.)
4. After the fix, `near-verbatim` has fallen and the total still reads 100% traced.
5. One chapter of concepts **read** against its source by a human — the waypoint's actual
   standard. Only this criterion can move the node's sounding from `proxy` to `observed`.

## Build

_Filled in as it happens: decisions taken, and why._

`scripts/check_grounding.py` written and run; the table in Problem above is its output.

`repair_model_text` + `_decode_byte_fallback` + `_restore_backslashes` in
`concepts_extract.py`, wired into `parse_concepts_response` ahead of `_norm_part`, with the
section markdown threaded from the call site as ground truth. Exported from the package
facade.

**One bug worth recording, because it is the same shape as the thing being fixed.** The first
version of `_restore_backslashes` used `re.sub(..., "\\" + letter, s)`. A replacement
*string* is re-scanned by `re`, so `"\\" + "t"` was read back as the escape `\t` — the repair
silently reinserted the very control character it was removing, and the tests failed with
output identical to the corrupt input. It takes a lambda now. Escaping bugs do not announce
themselves; they produce plausible text.

`scripts/repair_concept_sources.py` — dry-run by default, and the two repairs are decided
separately because they have different standards of proof. Byte decoding is not a guess and
applies unconditionally; backslash restoration is, and is gated on the section text. A row
that is already findable is never touched.

The script also had to stop passing the section markdown as ground truth for `signal`:
`signal` is the model's own explanation, not a quote, so gating its repair on whether the
*source* field matched was checking the wrong thing. It gets the safe set, exactly what a
fresh extraction would now store.

## Test

_What was actually run, and what it said._

**Backend suite: 147 passed, 1 xfailed.** Hub contract holds. Eight new tests in
`test_concepts.py` pin the chain end to end — including that a real tab between words is
*not* rewritten, and that a wrapped line is not turned into a `\n` macro, which is the
regression the risky set could cause.

**Backfill, applied to the live database** (rows backed up first):

| | |
|---|---|
| byte-escaped characters before | 30 rows |
| **byte-escaped characters after** | **0** |
| verbatim quotes | 1,265 → **1,284** |
| near-verbatim | 117 → **103** |
| traced to their own section | 1,463 / 1,463, unchanged |

**What is still broken, and why it is being left.** Four `signal` values carry `\n`
collisions — `\not`, `\nabla` — that cannot be repaired: `signal` is authored text, so there
is no ground truth to check a repair against, and rewriting every newline-plus-letter into a
macro would corrupt far more than it fixed. They will clear on the next re-extraction of
those sections, since the parse path is now fixed. Recorded rather than guessed at.
