Sub-cycle plan under [[0.) Development Protocol 1.0]]
Opened 2026-08-22

> FSRS retrievability holds across a real book I actually studied, over a season

## Arc amendment

The goal prompt [[GOAL PROMPT — Say what you did (v0.15.0 → v0.17.0)]] scheduled v0.16.0 as
"Delete means delete" and v0.17.0 as "Jobs that admit failure". This cycle displaces both by
one: **v0.16.0 is the TTS swap, delete work becomes v0.17.0, jobs become v0.18.0.** The goal
prompt is fossilised and is deliberately *not* back-edited; this note plus ADR 0002 are the
amendment, per the protocol's "corrections go to ADRs, never back-edits".

The reordering is not arbitrary. The TTS finding arrived with a measurement attached and a
24× payoff, and it *shrinks* the later cycles: deleting the checkpoint subsystem removes the
code that finding C8 lives in, and it removes TTS from the queue's concerns before v0.18.0
tries to make the queue honest. Doing it first means the two deferred cycles get smaller,
not just later.

## Problem

Audiobook generation was too slow to use: a one-hour chapter cost ~53 minutes of GPU as
shipped. Tuning the batching (2 → 8 Ollama slots, and setting `AUDIOBOOK_TTS_WORKERS`, which
had been defaulting to 2 while the server offered more) brought that to ~25 minutes. That
lever is now spent — scaling is sublinear and oversubscription reverses it.

The remaining cost is structural. Orpheus is a 3B autoregressive LLM emitting 7 audio tokens
per frame, so every frame of audio pays a full transformer decode on a bandwidth-bound chip;
SNAC decode is only 7% of wall time. Concurrency hides latency, it does not reduce work.

Kokoro-82M, measured on this box, renders the same chapter in **5.6s instead of 132.7s**.
Full numbers and the alternatives considered are in ADR 0002.

## Appetite

One sub-cycle. This is a swap behind an existing seam plus a deletion — if it grows past
that, something is wrong with the seam and the cycle should abort rather than expand.

## Plan

1. **A Kokoro engine behind the existing `synthesize()` seam.** `tts_orpheus.synthesize(text,
   voice) -> np.ndarray` is already the right boundary; add `tts_kokoro` satisfying it and
   select via env (`AUDIOBOOK_TTS_ENGINE`, default `kokoro`). Orpheus stays importable for one
   cycle so the comparison is reproducible, then goes.
2. **Delete the checkpoint/resume subsystem.** Per-chunk `.npy` writes, `_load_manifest`,
   `_work_dir`, the resume path, and the `interrupted` status. At six seconds a chapter this
   protects nothing. Retires audit finding **C8** by deleting its host.
3. **Drop the concurrency machinery.** `_TTS_GATE` and `AUDIOBOOK_TTS_WORKERS` both go —
   measured 50.4× / 51.9× / 49.0× at 1 / 4 / 8 streams, so a pool buys nothing.
4. **Revert `OLLAMA_NUM_PARALLEL` to 2**, giving the fleet's larger models their KV headroom
   back. It was raised to 8 for Orpheus alone.
5. **Voice**: default `af_bella` (the only A-graded English voice), pending the ear check.
   `af_nicole` excluded on measurement — 37.4s for a paragraph the others read in 21–27s.
6. **Frontend**: `audiobook.ts:9`'s status union loses `'interrupted'` along with the backend
   state. Also fix **E6** while here — the panel's unhandled rejection leaves the UI spinning
   forever when generation fails, and its `started.status === "error"` guard is dead code
   because the route returns 503 and `parseJsonResponse` throws first.

**Non-goals.** No voice cloning. No streaming/TTFB work — this is batch narration and
time-to-first-packet does not matter. Not touching the queue's honesty problems (v0.18.0), and
not building the per-chunk ASR validation the research recommends: at six seconds a chapter,
re-rendering is the cheaper mitigation, and adding a validator would re-import the complexity
this cycle deletes.

## Exit criteria

1. A chapter renders in **under 15 seconds** end to end via `make_audiobook`, verified on the
   same DDIA chapter used for the baseline (132.7s → target ≤15s).
2. The checkpoint subsystem is **gone**, not disabled — `_work_dir`, manifest and `.npy`
   handling deleted, and no `interrupted` status anywhere in backend or frontend.
3. A full book (not one chapter) renders without a dropped or repeated segment. This is the
   one thing the research says is genuinely unproven for any model, so it is the criterion
   most likely to fail and must not be skipped.
4. Audio is auditioned by ear on real textbook prose before the tag — quality is the accepted
   trade here, so a measurement cannot close this cycle on its own.
5. `NUM_PARALLEL` back to 2 with the rest of the fleet healthy.

## Build

Landed:

- **`tts_kokoro.py`** satisfies the existing `synthesize(text, voice) -> np.ndarray` seam,
  so nothing in `make_audiobook` had to learn about the swap. One shared `KPipeline`, built
  lazily so the API process does not pay the torch/spaCy import unless something narrates.
- **`make_audiobook` renders straight through.** Gone: the work dir, per-chunk `.npy`
  checkpoints, `_load_manifest`, `_save_chunk`, `_load_checkpoint`, the resume path, the
  `interrupted` status, `_TTS_GATE`, `_TTS_WORKERS` and the `ThreadPoolExecutor`.
- **Finding C8 retired by deletion.** A segment that synthesizes to silence is now *counted*
  and returned as `silentSegments` rather than skipped — the old code wrote it as a valid
  zero-length checkpoint that a resume would never retry, so a sentence vanished silently.
- **`OLLAMA_NUM_PARALLEL` back to 2**, `AUDIOBOOK_TTS_WORKERS` removed entirely.
- **Frontend**: the `'interrupted'` status is gone from the union; `af_bella` replaces the
  `"tara"` seed in the picker; **E6** fixed — `poll`, the scope effect and `generate` all
  had unhandled rejections that left the panel spinning forever with no message when the
  service was down, and the scope effect additionally had no staleness guard.

Two deviations from the plan, both deliberate:

1. **`tts_orpheus.py` deleted now, not next cycle.** The plan kept it one more cycle for
   reproducibility, but removing `snac` from requirements would have left a module that
   cannot import — a landmine, not a reference. Git history and ADR 0002 preserve the
   comparison.
2. **Three hardcoded `"tara"` defaults found and fixed** (`media_routes.py`, and two in the
   panel). Not in the plan because I had not noticed them; they would each have silently
   fallen back to the engine default on a voice that no longer exists.

## Test

**Exit criterion 1 — PASS.** Same DDIA chapter, through the real service, `make_audiobook`
end to end: **10.3s** on a fresh pipeline (includes the ~2s model load), **5.4s** warm
(56.1× realtime) against a 15s bar. Baseline was 132.7s.

| | wall | realtime |
|---|---|---|
| Orpheus as shipped | ~282s | 1.13× |
| Orpheus tuned (8×8) | 132.7s | 2.40× |
| **Kokoro, warm** | **5.4s** | **56.1×** |

**Exit criterion 3 — PASS, at genuine book scale.** A 622-segment chapter rendered
**1 hour 56 minutes of audio in 123.2 seconds** (56.5×), status `done`, zero silent
segments, MP3 intact at 116.0 min. This was the criterion flagged as most likely to fail —
the research found long-run robustness unproven for every model — and it held.

The ledger makes the before/after unambiguous, same engine change, real jobs:

| scope | segments | audio | render | realtime | engine |
|---|---|---|---|---|---|
| toc:2 | 438 | 4837.4s | 4925.2s | 0.98× | Orpheus |
| toc:1 | 51 | 643.4s | 518.3s | 1.24× | Orpheus |
| toc:2 | 135 | 1680.3s | 1415.6s | 1.19× | Orpheus |
| **toc:1** | **622** | **6957.7s** | **123.2s** | **56.5×** | **Kokoro** |
| **toc:acknowledgments** | **23** | **303.1s** | **5.0s** | **60.6×** | **Kokoro** |

**Criterion 2 — PASS.** `_work_dir`, `_load_manifest`, `_save_chunk`, `_TTS_GATE`,
`_TTS_WORKERS` all absent from the module; no `interrupted` in backend or frontend.
**Criterion 5 — PASS.** `NUM_PARALLEL=2`, fleet healthy, GPU intact across the restarts.

Suite: 126 passed, 3 failed — all three `test_toc_controller`, none of them this cycle's.
Two pre-date v0.15.0; the third (`test_behavior_lock[pagematched]`) arrived with `6a54ae6`
from a parallel session. `test_audiobook.py` passes. Hub contract holds with the new
`conductor → media` warm-up edge. `tsc --noEmit` clean.

**Three measurement bugs caught, all the same shape.** Each hid a one-time cost inside a
timed region and produced a wrong number:

1. The parallel Kokoro benchmark built a `KPipeline` per worker thread, so the model load
   landed in the timing — made concurrency look actively harmful (30×/21×) when it is flat.
2. misaki downloads spaCy's `en_core_web_sm` on *first use*, mid-render. A runtime network
   dependency in a keyless-local system, and ~15s on the first narration. Baked into the image.
3. The Kokoro weights themselves were also fetched at first use. Also baked.

Then a fourth, worth recording separately because it invalidated a *fix* rather than a
measurement: after adding the startup warm-up, `docker exec python -c` still reported ~18s —
because it spawns a **separate interpreter** that never sees the uvicorn process's warmed
pipeline. The warm-up was working; the probe was measuring the wrong process. Measuring
through the real queue gave 5.0s. General lesson: a probe that runs beside the service
instead of inside it can only measure a cold path.

_Remaining: criterion 4 (ear check — quality is the accepted trade here, so it cannot be
closed by measurement)._
