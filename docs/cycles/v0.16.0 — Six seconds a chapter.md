## Arc amendment

The goal prompt [[GOAL PROMPT — Say what you did (v0.15.0 → v0.17.0)]] scheduled v0.16.0 as
"Delete means delete" and v0.17.0 as "Jobs that admit failure". This cycle displaces both by
one: **v0.16.0 is the TTS swap, delete work becomes v0.17.0, jobs become v0.18.0.** The goal
prompt is fossilised and is deliberately *not* back-edited; this note plus ADR 0002 are the
amendment, per the protocol's "corrections go to ADRs, never back-edits".

The reordering is not arbitrary. The TTS finding arrived with a measurement attached and a
24× payoff, and it *shrinks* the later cycles: deleting the checkpoint subsystem removes the
code that finding C8 lives in, and it removes TTS from the queue's concerns before v0.18.0
tries to make the queue honest. Doing it first means the two deferred cycles get smaller,
not just later.

## Problem

Audiobook generation was too slow to use: a one-hour chapter cost ~53 minutes of GPU as
shipped. Tuning the batching (2 → 8 Ollama slots, and setting `AUDIOBOOK_TTS_WORKERS`, which
had been defaulting to 2 while the server offered more) brought that to ~25 minutes. That
lever is now spent — scaling is sublinear and oversubscription reverses it.

The remaining cost is structural. Orpheus is a 3B autoregressive LLM emitting 7 audio tokens
per frame, so every frame of audio pays a full transformer decode on a bandwidth-bound chip;
SNAC decode is only 7% of wall time. Concurrency hides latency, it does not reduce work.

Kokoro-82M, measured on this box, renders the same chapter in **5.6s instead of 132.7s**.
Full numbers and the alternatives considered are in ADR 0002.

## Appetite

One sub-cycle. This is a swap behind an existing seam plus a deletion — if it grows past
that, something is wrong with the seam and the cycle should abort rather than expand.

## Plan

1. **A Kokoro engine behind the existing `synthesize()` seam.** `tts_orpheus.synthesize(text,
   voice) -> np.ndarray` is already the right boundary; add `tts_kokoro` satisfying it and
   select via env (`AUDIOBOOK_TTS_ENGINE`, default `kokoro`). Orpheus stays importable for one
   cycle so the comparison is reproducible, then goes.
2. **Delete the checkpoint/resume subsystem.** Per-chunk `.npy` writes, `_load_manifest`,
   `_work_dir`, the resume path, and the `interrupted` status. At six seconds a chapter this
   protects nothing. Retires audit finding **C8** by deleting its host.
3. **Drop the concurrency machinery.** `_TTS_GATE` and `AUDIOBOOK_TTS_WORKERS` both go —
   measured 50.4× / 51.9× / 49.0× at 1 / 4 / 8 streams, so a pool buys nothing.
4. **Revert `OLLAMA_NUM_PARALLEL` to 2**, giving the fleet's larger models their KV headroom
   back. It was raised to 8 for Orpheus alone.
5. **Voice**: default `af_bella` (the only A-graded English voice), pending the ear check.
   `af_nicole` excluded on measurement — 37.4s for a paragraph the others read in 21–27s.
6. **Frontend**: `audiobook.ts:9`'s status union loses `'interrupted'` along with the backend
   state. Also fix **E6** while here — the panel's unhandled rejection leaves the UI spinning
   forever when generation fails, and its `started.status === "error"` guard is dead code
   because the route returns 503 and `parseJsonResponse` throws first.

**Non-goals.** No voice cloning. No streaming/TTFB work — this is batch narration and
time-to-first-packet does not matter. Not touching the queue's honesty problems (v0.18.0), and
not building the per-chunk ASR validation the research recommends: at six seconds a chapter,
re-rendering is the cheaper mitigation, and adding a validator would re-import the complexity
this cycle deletes.

## Exit criteria

1. A chapter renders in **under 15 seconds** end to end via `make_audiobook`, verified on the
   same DDIA chapter used for the baseline (132.7s → target ≤15s).
2. The checkpoint subsystem is **gone**, not disabled — `_work_dir`, manifest and `.npy`
   handling deleted, and no `interrupted` status anywhere in backend or frontend.
3. A full book (not one chapter) renders without a dropped or repeated segment. This is the
   one thing the research says is genuinely unproven for any model, so it is the criterion
   most likely to fail and must not be skipped.
4. Audio is auditioned by ear on real textbook prose before the tag — quality is the accepted
   trade here, so a measurement cannot close this cycle on its own.
5. `NUM_PARALLEL` back to 2 with the rest of the fleet healthy.

## Test

_What was actually run, and what it said._

Baseline to beat, measured 2026-08-22 on the DDIA acknowledgments chapter (25 segments,
4,415 chars): Orpheus 8×8 → 132.7s wall for 318.6s of audio (2.40×). Kokoro single-stream
prototype → 5.6s for 288.5s (50–52×). The prototype ran in a throwaway container off
`compose-learn:latest`; the cycle has to reproduce it inside the real service.
