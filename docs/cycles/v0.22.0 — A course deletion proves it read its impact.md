# v0.22.0 — A course deletion proves it read its impact

Sub-cycle plan under [[0.) Development Protocol 1.0]]
Opened 2026-09-05

Addresses **Make learning more efficient**

> Each of fidelity, retention, competency and engagement carries evidence from one real book I studied end to end — not a demo corpus, and not the same book for all four

## Problem

`DELETE /api/document?doc=` removed a course, every version of it, the study rows keyed to those
versions and the audiobooks, on a single call with no read before it. There was no route that
said what would go. For an agent driving the API that is the cheapest possible path to the most
expensive mistake in the app: a book someone studied end to end, gone with its retention history.
This is the learnhub leg of the fleet-wide cycle "A destructive write proves it read its impact"
(shipyard `06f605b0144f`, shipyard v0.35.0, mission-control v0.3.0, helm v1.8.1); learnhub has
no chart problem of its own for it, so this record is the card.

## Appetite

Part of one evening. One new read, one gate, two call sites.

## Plan

`documents.deletion_impact(doc_id)` — read-only, the same source/version resolution as
`delete_document`, counting the study rows each cascade table would lose. The api layer adds the
audiobook count (it may import supplemental; the process layer may not) and issues a token
(`app/tokens.py`, copied verbatim from shipyard). `api_delete_document(doc, token)` recomputes
the impact and refuses 422 without a matching token, naming the read.

**Non-goals.** No shared token package across repos. No change to `delete_document`'s
transaction. No confirm-dialog redesign — the table and the shelf read the impact and pass the
token where they already had a confirm.

## Exit criteria

1. A bare `DELETE` on a real course returns 422 naming `GET /api/document/deletion`, and the course is still there.
2. The read returns source, versions, study rows, audiobooks and a token, and changes nothing (row counts before and after are equal, against Postgres).
3. A token for another course is refused by name; the suite stays green.

## Build

- `backend/app/tokens.py` (copy of shipyard's), `documents.deletion_impact`, `GET /api/document/deletion`, the token parameter on `DELETE /api/document`.
- `pipeline.ts`: `fetchLearnDeletion(doc)` and `deleteLearnDocument(doc, token)` — the second parameter is required, so a call site that skips the read no longer type-checks.
- `documents-table.tsx` and `course-shelf.tsx` read then delete; a failed read is a failed delete.
- **Decision:** the audiobook count is a check, not the verdict — if the media layer errors the read still answers with `audiobooks: null` rather than blocking the delete on an unrelated failure.

## Test

`backend/.venv/bin/python -m pytest tests -q` → **168 passed, 30 skipped, 1 xfailed** (3 new in `test_deletion_token.py`).
`LEARN_PG_TESTS=1 … pytest tests/test_delete_pg.py` against the dev Postgres (:5433) → **10 passed**, including the new `test_deletion_impact_reads_without_removing`.

Live, after `docker compose build learn app && up -d` (2026-09-05), against the real course
`56721433-c469-45f0-a73e-cbdc9c8df4f1`:

```
$ curl "localhost:8010/api/document/deletion?doc=not-a-doc!"
{"error":"invalid doc id"} 400
$ curl -X DELETE "localhost:8010/api/document?doc=56721433-…"
{"error":"refused: read GET /api/document/deletion?doc=… first and pass its token — the impact is what you are agreeing to"} 422
$ curl "localhost:8010/api/document/deletion?doc=56721433-…"
{doc, source: 56721433-…, exists: True, versions: [56721433-…], study_rows: {}, audiobooks: 0, token: <issued>}
$ curl "localhost:8010/api/document?doc=56721433-…"   → 200   (still there)
```

The sanctioned delete-with-token was exercised only against Postgres in the test, not on a live course — nothing real was worth deleting to prove it.

## Review

- The read had to be written in the process layer and the token issued in the api layer because of the import contract (process may not import supplemental). The seam was already there; the feature followed it.
- `deleteLearnDocument` now requires a token at the type level. That is the cheapest guard in the whole cycle and the one most likely to catch a future call site.
- Open: the Next proxy forwards `token` as a query parameter unchanged (`[...path]/route.ts` passes the query through) — verified by the shelf working in the built image, not by a test.
