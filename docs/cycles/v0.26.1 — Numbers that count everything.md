# v0.26.1 — Numbers that count everything

Sub-cycle plan under [[0.) Development Protocol 1.0]]
Opened 2026-11-09

Addresses **Make learning more efficient**

> Each of fidelity, retention, competency and engagement carries evidence from one real book I studied end to end — not a demo corpus, and not the same book for all four

## Problem

Four correctness bugs from Backlog, all user-visible:

- **Per-section mastery drops chapter-level concepts.** The rollup sums descendant leaves only.
  On prod (2026-11-09, read-only) 227 concepts across six books count in "overall" and in no
  section. The Python Language Reference alone has 97 of 854 missing.
- **Two books with no course card cannot be deleted** (Axler, Durrett). The shelf lists cards,
  and the delete dialog lives on a card.
- **Reading position is keyed to the course card**, so every version of a book shares one
  position, and a section key from one outline is offered in another.
- (The fourth, the root sandbox, shipped in v0.26.0.)

Opened under the human's 2026-11-09 `/goal`, as v0.26.0 was.

## Appetite

Half a session.

## Plan

1. `mastery.subtree`: a section's numbers sum itself and its whole subtree (cycle-safe).
2. Library: "Books without a course" lists learn documents no card points at, and each Delete
   goes through the existing deletion-impact read and token.
3. Reading positions: `v:<docId>` per version. The bare courseId stays the card's Continue and
   follows the main version on a switch. A legacy position is used only if its section exists
   in the current outline.

**Non-goals.** Deleting Axler or Durrett. That is the human's call, and irreversible. The card
opening the main version (Backlog: "cards resolve their own learn_doc_id") is a different
seam. Five PE2 concepts sit on sections outside its outline; that is an outline question, not
a rollup one.

## Exit criteria

- For each affected book, the sum of root-section totals equals the concepts in the outline.
- The Library shows both cardless books with a Delete that reaches the impact read.
- Moving chapters writes a `v:` position, and the card's Continue is unchanged.

## Review

**What did the plan miss?** That the reader saves a position only on a chapter change. My
first check (open a chapter, look for the key) could not have passed, and it looked like a
bug.

**What did the agent need that the prompt did not give?** Nothing new. The Backlog entries
were precise enough to build from.

**What did I learn?** Counting against an independent total (concepts in the outline) beats
eyeballing rollups. My first ad-hoc root heuristic (`no dot in the key`) gave 903 > 854 and
would have "proved" a bug that wasn't there.

Decision: ship.
