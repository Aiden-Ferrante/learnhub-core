# v0.19.2 — Match

Light cycle plan under [[0.) Development Protocol 1.0]]
Opened 2026-08-30

Addresses **Habit**

> A month where active days outnumber inactive days without me forcing it

Parent **Engagement**'s falsifier is the thing this attacks directly:

> The only days I open it are days something is due — the schedule is the whole reason I
> am here, and without it the app is inert

## Problem

Every activity Learn Hub has is scheduled. Concept recall, skeleton recall, and now the
practice session all surface work *because it came due*, which means the app has nothing to
offer on a day the queue is empty — and a day with nothing due is a day you do not open it.
That is Engagement's falsifier stated as a mechanism rather than a worry.

What is missing is something with **no cost of entry and no consequence**: openable in a
spare two minutes, over material you already have, that does not touch your schedule and
cannot put you behind. Quizlet's Match is the proven shape — a grid of terms and
definitions, click to pair, race your own clock.

The cheap part is that **it needs no generation at all.** `ext_concepts` already holds
605 name/signal pairs for the course being studied, extracted long ago. Every other game in
this arc (MCQ, ordering) needs an authoring pass first; this one needs a screen.

## Appetite

One sitting, frontend only. If it overruns, the timer and best-time go first — the grid
is the game.

## Plan

1. **`match-game.tsx`** in `surfaces/practicing/`: six concepts sampled from the chapter,
   twelve shuffled tiles (name ‖ signal), click a tile then its partner, matched pairs
   leave the board, mismatches flash and clear. A clock that starts on first click, a
   best-time-per-chapter in `localStorage`, and a "play again" that reshuffles a new sample.
2. **Mask the concept's own name inside its signal.** Measured on the live course:
   **204 of 605 signals (34%) contain their own concept name** — "Fuzzy logic is a formal
   system…" opposite the tile reading "Fuzzy logic". A third of the board would be solvable
   by string-matching rather than by knowing anything, which would make the game feel
   pointless within one round.
3. **Drill only.** One `record_engagement(kind="game")` per completed round through the
   existing `/api/engagement` route — which takes any kind string, so this needs **no
   backend change at all**. Nothing touches `concept_reviews`, nothing moves FSRS, nothing
   can put you behind. Precedent: `skeleton-practice.tsx`'s sort mode, "Drill only —
   sorting never changes your schedule."
4. **A mode switch inside the existing Practice surface**, not a sixth nav tab. Commit
   `99e4279` deleted seven study modules for being too many activities; this arc adds
   modes to one surface rather than surfaces.

**Non-goals.** No new tables, no LLM, no job, no schedule effects, no scoring that persists
anywhere but this browser. No leaderboard. Not a measure — the measure for this node is a
month of activity days, which only time can produce.

## Exit criteria

1. Match is playable on a real chapter with **zero generation having run** — it reads the
   concepts already there.
2. No tile pair is solvable by reading the concept's name out of its own definition.
3. A completed round moves the activity heatmap (`byKind.game`) and leaves
   `concept_reviews` **byte-identical** — verified by row count and content before/after,
   live, not by reading the code.
4. It is playable in under two minutes from opening the course, with no setup.

## Build

Frontend only, as planned — `/api/engagement` takes any kind string, so `kind="game"`
needed **no backend change at all**.

**`game` deliberately NOT added to `sessions._PASSIVE`,** against the sketch in the
v0.19.0 plan. `_PASSIVE` decides which kinds may *name* a session, and a game is deliberate
practice, not consumption. It only changes the answer for a game-plus-reading session:
outside `_PASSIVE` that is a "game" session, inside it becomes a "read" one — and the first
is the truer description of what you did. Games remain non-graded (`correct IS NULL`), which
is what keeps them out of every accuracy figure; that property comes from the event shape,
not from this set.

**Three things the real board taught, none of which a test would have.**

1. **Masking whole terms only.** The first cut masked every component word of a multi-word
   term, so "Hilbert systems" turned the unrelated phrase *"proof systems"* into
   *"proof —"*. Now the full phrase is always masked, and a component word only when it is
   ≥6 characters and not in a small generic-noun list (`system`, `structure`, `logic`,
   `proof`, `term`…). "Quantifiers" is blanked; "systems" is not.
2. **Concept signals carry TeX.** A tile rendered `$P \rightarrow Q$` as `$P ightarrow Q$` —
   the backslash-r eaten as a control character. Definition tiles now render through
   `MathText`, which exists in the reading surface for exactly this layer ("the
   LLM-generated layer — concept signals…"). Term tiles stay plain text.
3. **A transient documents fetch could destroy a round in progress** — and this is the find
   worth keeping. `course` is derived from the shared documents list; a 401 on a stale
   session empties it, `course` goes null, every course page falls to `CourseFallback`, and
   the subtree UNMOUNTS. For the reader that is a blink. For the practice session it drops
   your revealed card. For a timed game it is fatal, and that is the only reason it was
   noticed at all. `use-course-data.ts` now keeps the last good course for the life of the
   mount, so a blink in the documents list can no longer wipe study state on any surface.
   Navigating to another course remounts the hook, so a stale book cannot be served.

## Test

Against the real course (AI 101 — Mathematics for ML, chapter 1, 605 concepts), in the
running app — no fixtures, and there is no frontend test runner in this repo to hide behind.

- **Zero generation.** The board is dealt from `ext_concepts` alone; nothing was authored,
  no job ran.
- **No giveaway tiles.** Across boards inspected tile-by-tile, **0 definitions contained any
  term present on their board** (the check compares each definition against all six terms,
  which is stricter than checking only its own partner). Sample after the masking fix:
  *"— are proof systems characterized by many axiom schemes and only one rule of
  inference"* — the term blanked, the unrelated phrase intact.
- **Math renders.** KaTeX nodes present on a board that previously showed raw TeX.
- **A full round, played through the UI:** *"Cleared in 55.8s with no misses — a new best."*
- **The drill-only contract, verified live rather than reasoned about.** `concept_reviews`
  before the round: 59 rows, md5 `86f28e95b5db66cc06ccb9b1c7d61d05`. After: **59 rows, md5
  `86f28e95b5db66cc06ccb9b1c7d61d05`** — byte-identical. `study_events` gained exactly one
  `kind='game'` row scoped `toc:1`, and the activity heatmap reads
  `{read: 21, review: 85, practice: 3, game: 1}`.
- 55.8s from a cold board, so exit criterion 4 (playable in under two minutes) holds with
  room, and the backend suite is untouched at 159 passed.

## Review

**The game found a bug in the app around it, not in itself.** Two of the three build notes
above are defects that predate this cycle and affect other surfaces — the remount especially,
which has been silently discarding study state on every course page for as long as the
documents fetch has been able to fail. A timed game is unusually sensitive to that class of
fault: a reader loses a scroll position and shrugs, a clock loses everything and you notice
in the first minute. Cheap activities are worth building partly because they are good
detectors.

**Automating a game is harder than playing one, and the automation lied twice.** Programmatic
`.click()` silently did nothing (only `dispatchEvent` reached React's handler), and several
clicks batched into one call all read the same stale state, so early "0/6 pairs" readings
looked like a broken matcher when the game was fine. Both would have been reported as
product bugs by a less suspicious pass. The rule that saved it was checking the DOM's own
state rather than trusting that an action had happened.

**Still unmeasured, by construction.** This cycle ships an *activity*. Habit's waypoint is a
month where active days outnumber inactive, and nothing here can shorten that — the only
evidence that matters arrives by playing it on days nothing is due, or fails to arrive.
The sounding on that node stays `assumed`.
