# v0.28.0 — Calm reading room

Sub-cycle plan under [[0.) Development Protocol 1.0]]
Opened 2026-11-09

Addresses **Make learning more efficient**

> Each of fidelity, retention, competency and engagement carries evidence from one real book I studied end to end — not a demo corpus, and not the same book for all four

## Problem

Backlog, human 2026-11-04: "Make the visuals more pleasing." Chosen feel: *calm reading room*:
a warmer dark, softer contrast, more breathing room, a serif body for reading and sans labels.
Dark only. Screens: Library + course home, Reading, Exam packs, Review + recall.

## Appetite

Half a session.

## Plan

One scoped theme, not a per-screen restyle. Every screen reads the same tokens, so moving the
tokens moves all four at once.

- `.room` wraps page content in `layout.tsx` and restates the shadcn tokens and the `--fleet-*`
  aliases on a warm ground (hue 30–38, low saturation).
- The header is **outside** `.room`. It is shared fleet chrome and must keep matching the
  siblings (`fleet-ui/check.sh` live check).
- Air: sheet padding 20/22 → 28/32 (18/20 on phones), sheet gap 0.75 → 1 rem, choices and notes
  roomier, the study grid fainter (45% → 22%).
- Serif (`--reading-serif`, already the paper reader's) for markdown body text, pack chunks and
  concept statements. Headings, labels, buttons and choices stay Geist.

**Non-goals.** A light mode. The header. Changing `fleet-study.css` (a checked byte-copy of the
fleet's block). New type sizes (the checker allows six). The paper reading mode.

## Exit criteria

- `fleet-ui/check.sh` clean against the deployed build, including the header live check.
- Body contrast stays above WCAG AA (4.5:1) everywhere it changed.
- Before/after screenshots of each screen, looked at.

## Build

- One commit: `feat(theme): the calm reading room`.
- Found while building: the `--fleet-*` aliases resolve at `:root`, so overriding
  `--background` in a subtree alone would have left every study-kit surface on zinc. They are
  restated in `.room`.
- Found by looking: the pack chunk is a plain list, not markdown, so it stayed sans in the
  first after-shot. It now takes `.reading`. Concept statements take `.concept-md`.
- A first draft forced code inside serif text to `var(--font-mono)`, which is undefined in this
  app and would have swapped Geist Mono for the system mono. Dropped: code sets its own face.

## Test

- Contrast (WCAG, computed from the tokens): ink/ground 18.1 → **13.9:1**, ink/card **12.8:1**,
  faint/card 6.9 → **6.6:1**. All above 4.5:1.
- `fleet-ui/check.sh`, run against the deployed image: "live check: clean — 6 running apps
  render the same header", and "every colour, type size, face and focus ring … comes from
  fleet.css".
- `next lint` 0 errors, tsc clean, hub contract holds.
- Screens on :3001 (the human's Chrome), in `assets/v0.28.0/`: `before-{library,reader,pack}`
  and `after-{library,course-home,reader,pack,review}`. Looked at each one. The ground and
  sheets are warm brown-black, the header is unchanged zinc, the reader body is serif at line
  height 1.75, pack chunk bullets are serif with mono citations, and the grid behind is fainter.

## Review

**What did the plan miss?** That "serif body" needs a definition of *body*. Three different
components render reading text (markdown, the chunk list, concept markdown). Only looking at
the pack screen showed the second.

**What did the agent need that the prompt did not give?** Whether "warmer" should reach the
header. I took the fleet's rule (shared chrome matches siblings) and left it. If the human
wants the header warm too, that is a fleet-wide decision, not a LearnHub one.

**What did I learn?** Scoped theming through CSS custom properties has one trap: aliases that
resolve where they are declared. Restating them in the scope is the fix, and it is invisible
in the source until you render it.

Decision: ship.
