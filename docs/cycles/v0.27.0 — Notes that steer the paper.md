# v0.27.0 — Notes that steer the paper

Sub-cycle plan under [[0.) Development Protocol 1.0]]
Opened 2026-11-09

Addresses **Make learning more efficient**

> Each of fidelity, retention, competency and engagement carries evidence from one real book I studied end to end — not a demo corpus, and not the same book for all four

## Problem

The goal's item 4 named three 11/01-design features as unbuilt: scope notes that weight
questions, exam practice feeding FSRS per skill, and a resit with fresh questions. Reading the
code showed the last two were already built (`_grade_skill` under one `pack-` row per skill,
and `pack_seen` keeping every sitting unseen). The first was built in name only:

- A skill's weight (from scope notes, at build time) only **ordered** items inside a chapter.
  Every item still came up in turn, so notes changed nothing about a paper's mix.
- Notes could be set only when a pack was created. Changing them meant a full rebuild.

## Appetite

One session.

## Plan

1. `draw_paper`: within a chapter, each pick is drawn in proportion to weight
   (Efraimidis–Spirakis keys). Chapters still take turns.
2. `POST /api/packs/{key}/notes` stores notes and queues a reweight (the `pack` kind,
   `reweight=true`): one model call per chapter sets weights in [0.5, 3] from the notes, with no
   new questions. The pack receipt records the changes. Results gets a Scope notes panel.
3. Prove the two existing features on real data instead of rebuilding them.

**Non-goals.** Notes that add material (they never may). Weighting across chapters (the
human's rule is that a paper spreads across the picked chapters). Re-running grounding on a
reweight.

## Exit criteria

- On real items, a weight-2 skill is drawn about twice as often as weight 1.
- Editing notes on :3001 changes weights as the notes say, and the panel shows what changed.
- Two consecutive papers share no question. `pack-` FSRS rows exist per skill.

## Build

- `55606a1` weighted draw. `397d8a2` notes + reweight + panel. `ec121a5` jsonb casts + finally +
  PG tests. `fdd9953` building on save.
- **Decision (changes a tested behaviour):** a generator now serves at most 5 questions a paper,
  the capacity `pool_capacity` already credits it with. Without a cap, weighted picks let one
  high-weight generator fill a chapter. `test_a_generator_serves_many_distinct_instances` was
  updated from 6 to 5, and this note is why.
- Empty notes reset every weight to 1. A skill the model invents is ignored.

## Test

- pytest 195 passed (+ PG tier: 228 with `LEARN_PG_TESTS=1`). New: weight 3 vs 1 → ratio in
  (2.2, 4.0) over 200 papers, equal weights within 0.8–1.25, reweigh clamps/ignores/resets,
  3 real-Postgres tests of the pack writes.
- **Weighted draw on real items (PE1 Full book test, 100 papers, read-only):** draws per item:
  weight 1 → 7.97, weight 1.5 → 14.91, weight 2 → 14.75. The 2:1 ratio is ~1.85, slightly
  diluted by chapters taking turns.
- **Resit:** two consecutive papers from the same pack, 30 + 30 questions, **0 shared**.
- **FSRS per skill:** 6 `pack` review rows, 6 distinct skills (from the 11/03 sitting).
- **Live reweight, PE1 Operators pack (:3001, the human's Chrome; weights backed up first):**
  - Run 1, "Heavy on modulo and true division. Operator priorities are not on the exam." →
    weights modulo 3, true-division 3, priorities 0.5, rest 1. **But the job then failed:**
    `operator does not exist: jsonb || json` on the receipt write, leaving the pack in
    'building'. Both receipt merges (`reweight_pack`, `finalize_pack`, which every future
    build calls) had it. The stubbed tests passed. Fixed with casts and a `finally`, and the
    PG tests fail 3/3 on the bad commit and pass on the fix.
  - Run 2, "Floor division with negative numbers matters most." → floor-division 1 → 3 with
    the reason quoted, and the three earlier boosts reset to 1. **Second miss:** the panel kept
    showing the previous receipt. The pack only polls while 'building', and the worker set
    that after the page's refetch. Saving now sets 'building' at once.
  - Run 3, notes cleared → the panel updated by itself after 11 s: "changed 1 skill …
    3 → 1 (no scope notes)".
  - Restored: original weights (binding 2, floor-division 2, priorities 2, rest 1), empty notes,
    the reweight receipt removed.

## Review

**What did the plan miss?** That two of the three "unbuilt" features were built. My 11/09
survey was wrong about them, and reading `packs.py` corrected it before any code was written.

**What did the agent need that the prompt did not give?** A PG test tier run in the loop. Two
of this cycle's three misses were invisible to stubbed tests (SQL types, timing).

**What did I learn?** Any new SQL gets a real-Postgres test in the same commit. And "tests
pass" was false confidence twice in one cycle. Both misses were found only by driving the
real page.

Decision: ship.
