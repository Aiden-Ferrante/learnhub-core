## Exit criteria

1. A real chapter yields generated `retrieve` + `problem` items, judged by reading;
   receipt shows dropped/refused; zero furniture tells in stored prompts.
2. A contentless section yields a refusal (0 items, no error).
3. A hand-edited item survives section regeneration; an untouched one is replaced.
4. A distilled custom version inherits its book's items with no generation run.
5. A practice grade moves the heatmap and its own schedule, moves **neither coverage nor
   retention** (verified live), and never appears in the concept session.
6. Fluency reads a raw number with items, **unknown (—)** with none, and no surface
   averages it into retention.
7. Per the standing rule — render the real artifact: checks run against a real book in
   the running app, images rebuilt first.

## Build

_2026-08-28, one session._ Backend + frontend landed as planned; deviations worth noting:

- **`_TypedItem` gained an optional `event_doc` hook** instead of a practice-specific
  grade branch: practice review rows follow the BOOK (shared memory, like concepts) while
  the study event belongs to the VERSION studied — the same split `grade_review` already
  made for concepts, now expressible per typed kind.
- **The queue card carries answer/rubric read from `ext_practice` at queue-build time.**
  Nothing is snapshotted into `concept_reviews` (children stays NULL) — an edit in the
  Practice tab shows up on the very next session, and delete cascades the review row.
- **Retrieval grounding**: the prompt receives the section text AND the section's
  extracted concepts as grounding lines (spec wanted concepts; spike 1 validated text —
  both are supplied, the text capped at 20k chars).
- Dev environment rebuilt en route: `backend/.venv` was missing (recreated via uv), and
  the dev Postgres on :5433 that `.env.local` expects was gone — recreated as a scratch
  clone of the prod DB with the migration applied, which is also what made live
  verification possible without touching the running stack.

## Test

- Unit suite: **182 passed, 1 xfailed** (incl. 29 real-Postgres integration tests against
  the scratch clone with `ext_practice` present). New `tests/test_practice.py`: furniture
  filter catches both spikes' observed tells and passes real subject questions; authoring
  post-processing drops furniture, maps retrieve q/a, treats an empty list as refusal;
  queue cards carry live reveal fields and no children; `summarize_fluency` enforces all
  three rules.
- **Live run, 2026-08-28** — real library (scratch clone of the prod DB on :5433, real
  Ollama, `nemotron-3-nano:30b`), *AI 101 — Mathematics for ML*, chapter 1 (13 sections):

  1. ✅ Generation: 26 calls → receipt `{authored: 67, dropped: 6, refused: 0}`. Problems
     are real work (formalize a claim in quantifiers; the Wason card task with the two
     correct cards demanded and justified). Judged by reading.
  2. ⚠ Refusal: **still never observed from the model** (0 refusals — consistent with both
     spikes). The handling path (empty list → counted as `refused`, not an error) is
     unit-tested; the behavior remains untriggered on real sections.
  3. ✅ Regeneration: hand-edited one item (the "§6" prompt, rewritten as a subject
     question), then regenerated `kinds=["retrieve"]` — the edited item was the sole
     survivor of its kind, 34 fresh items replaced the unedited ones, the 31 problems were
     untouched.
  4. ✅ Inheritance: a custom version cut from Default returned all 44 then-existing items
     through `concept_filter` with zero generation.
  5. ✅ Separation: grading a practice item moved the heatmap (`byKind.practice`) and its
     own FSRS row; coverage stayed 54/605 and retention 93.5% before and after; the
     concept queue contained 0 practice cards; the calendar types the rows `practice`
     and names them by prompt.
  6. ✅ Fluency honesty: read **"—"** with no attempted problems; grading a RETRIEVE item
     did not move it (excluded denominator, by design); grading a PROBLEM flipped it to
     `{items: 11, attempted: 1, fluency: 1.0, state: "measured"}`. Retention unchanged.
  7. **The filter is living.** The first real run produced three furniture shapes neither
     spike showed — `§6`, "according to the introduction", "this introductory section" —
     all now in `_FURNITURE_TELLS` + pinned by tests. After regeneration under the new
     filter: **0 furniture tells across all 66 stored items**.
