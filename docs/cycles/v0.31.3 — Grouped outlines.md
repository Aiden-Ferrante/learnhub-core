## Problem

Python Essentials 1's course outline is flat. Its bookmarks list "Module 1: …" beside "1.1",
"1.2" at one level, the controller trusted that, and `curate_outline`'s orphan-part rule then
**hid** each Module heading (a childless top entry followed by a chaptered sibling). The tree
shows 1.1 … 4.7 as 23 top-level chapters, with "Welcome" and "Introduction" numbered 1 and 2 by
position.

The same orphan-part rule hides real study content in other books (prod survey 2026-11-19):

| Book | Hidden as orphan-part | Should be |
|---|---|---|
| Python Essentials 1 | Module 1–4 | visible parents of N.x |
| Mathematics for ML | Exercises ×6 | last child of the chapter before |
| Learning SQL | Appendix A | visible, like Appendix B and C |
| Linear Algebra Done Right | Preface for Students | front matter (as are its siblings) |
| Deep Learning with PyTorch | about the cover illustration | front matter |
| PyTorch, Python Language Reference | the book's own title entry | hidden (correct today) |

Nothing flagged any of it: `assess_bookmarks` already logs "all level 1 (nesting lost?)" and
routes on regardless.

## Plan

1. **Nest stage** in `toc_controller.py`, after canonicalize: a depth-0 container titled
   `Module|Part|Unit|Chapter|Week|Lesson N` followed by depth-0 siblings numbered `N.x` adopts
   them (and their subtrees) one level down; the container takes `N` as its number label. A
   childless top entry titled like an end-of-chapter section (Exercises, Problems, Summary, …)
   directly after a chapter becomes that chapter's last child.
2. **Narrow orphan-part.** It may hide only a Part/Unit-titled entry, or the book's title entry
   (the first top entry, childless). Front/back matter gains `preface …` and
   `about the cover illustration`.
3. **Flag it at ingest.** A new assess signal, `dotted-tops`: numbered `N.M` entries at depth 0.
   The decision log names it; the curate log already names every hidden title.
4. **Library-wide check**, `make check-outlines` (`scripts/check_outlines.py`, read-only on the
   DB): fails on a dotted number at depth 0, a hidden node that is not a Part/title/front-back,
   or a hidden container whose following siblings carry its number.
5. **Repair in place**, `scripts/restructure_outlines.py` (dry run by default, `--apply`):
   re-run the nest + curate stages over each book's stored outline and UPDATE depth, parent,
   kind, page span, number label and hidden reason. Section keys, and so node ids
   (`doc_id::section_key`), never change. Re-converting is ruled out: it deletes the outline
   and every concept anchored to it.

**Non-goals.** Synthesising parents the book never names (the "Chapter N without a number" ADR
seed stays open). Re-converting any book. The reader's two rails. Interleaving in the Mathematics
for ML AI 101 compilation (a separate document).

## Exit criteria

- PE1's Overview tree shows Welcome, Introduction, Modules 1–4 with their sections nested, then
  the appendices; the chapter rail matches.
- MML shows each Exercises section under its chapter; Learning SQL shows Appendix A.
- `make check-outlines` passes on prod and fails on the pre-repair snapshot.
- Guardrail: per-book counts of concepts, review cards and structure ids are identical before and
  after the repair.
