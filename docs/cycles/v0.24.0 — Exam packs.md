# v0.24.0 — Exam packs

Sub-cycle plan under [[0.) Development Protocol 1.0]]
Opened 2026-11-01

Addresses **Exam packs**

> From Python Essentials chapters I picked, the app builds a pack with Learn and an exam, every item cited to a section, and I sit a generated paper with fresh numbers on resit; the receipt names what was kept, dropped and too thin

## Problem

The CSE-5709 midterm was studied in three hand-built artifacts, not here: `study_events` holds 10
reviews ever. They won on fresh numbers, instant marking, step-by-step Learn and exam-shaped
structure. They lost persistence: progress sat in `localStorage` and nothing carried forward.

## Decisions

**By the human, 2026-11-01:** pick chapters, short format form with per-course presets, optional
scope notes that weight but never add material. Anything uploaded as a course is a textbook and the
only source; every item cites a section. Use the book's summaries and problems where they exist,
generate where they don't. Book problems stay in Learn; exams show only unseen variants and
generated items; resits get new seeds. Conceptual chapters: scenario MCQs plus self-graded written
answers. Thin chapters are reported, never padded. Practice feeds FSRS by skill. Tabs: Today, Learn,
Exam, Results. Learn = stepper, single column. Exam = booklet with answer grid, one question at a
time. The look becomes a study theme in fleet.css. Build, then notify, with a receipt. First book:
Python Essentials. v0.23.0 closed first. Dev stack only: prod migration and image rebuild wait for
the human.

**Defaults taken where the human left it open (the agent's, reversible, flagged in the close-out):**
- Native React surface. The sandboxed widget host is NOT built: nothing in the picked scope needs a
  bespoke per-course tool yet. Pruned to Backlog.
- `gen` items are declarative specs plus Python snippets run in an isolated subprocess. Amends the
  practice spec's "fixed pool, no generate-on-demand" (ADR 0003); "no LLM in the graded loop" holds,
  because instances are computed at sit time by code checked at build time.
- Display: packs get their own per-course page; finished chapters open while others build; written
  answers mark on Results and the score stays provisional until they are; Match, skeleton recall and
  the old exam mode stay untouched.

## Appetite

One goal run. Shed order if it overruns: Today's time boxes, presets UI polish, then variants of
book problems (generated items alone still satisfy "unseen").

## Plan

Ladder, one commit per rung: (1) sandbox + generator + seed harness; (2) schema, pack store, draw,
sittings, Today, results, FSRS by skill; (3) routes; (4) authoring job with citations and receipt;
(5) study theme; (6) frontend; (7) verify on Python Essentials on dev.

Non-goals: widget host, porting midterm artifacts, the `code` kind, new work on old exam mode, prod.

## Exit criteria

1. On dev, a pack built from real Python Essentials chapters: every item carries a section citation
   whose evidence quote is found in that section. Pasted.
2. The receipt shows kept, dropped with reasons, and any thin chapter. Pasted.
3. Book problems appear in Learn and in no exam. Checked by query.
4. Two sittings of one pack differ in numbers and share no instance. Pasted.
5. Today, Learn, Exam and Results are opened in a browser against dev, screenshots read.
6. A graded answer moves a `pack-` FSRS row; a written answer leaves the score provisional.
7. `fleet-ui/check.sh` clean, backend suite green, frontend typechecks.
8. Guardrail: `reviews.py` gains only the typed item; old exam-mode behaviour unchanged.
