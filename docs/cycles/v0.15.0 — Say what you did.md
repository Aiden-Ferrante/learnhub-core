# v0.15.0 — Say what you did

Sub-cycle plan under [[0.) Development Protocol 1.0]]

> FSRS retrievability holds across a real book I actually studied, over a season

First sub-cycle of the arc in
[[GOAL PROMPT — Say what you did (v0.15.0 → v0.17.0)]].

## Problem

Learn Hub does not fail loudly. It fails **confidently** — HTTP 200 with a plausible,
wrong answer — and every surface renders that answer as fact. That directly attacks the
waypoint above: retrievability cannot "hold across a real book" if the thing reporting it
returns an empty review queue for a course full of due cards.

A 2026-08-21/22 audit read the upload, delete, persistence, study, content and frontend
layers end to end and found 44 verified issues. This cycle takes the ones where the app
gives a confident wrong answer, plus the two auth holes that are cheap to close alongside.

Three repeated mistakes underneath them:

- **The book/version seam crossed the wrong way, silently.** Four SQL sites key a
  source-scoped table by a version id, or compare the two keyspaces directly. Because both
  ids are opaque strings, the result is an empty set rather than an error.
- **`except Exception: return {}` as the house style for reads.** A transient DB error
  becomes "you have studied nothing".
- **An endpoint dead for weeks with nobody noticing.** `/api/engagement` raised a
  `TypeError` on every call since it shipped, and the client fires it fire-and-forget.

## Appetite

One sub-cycle. Correctness only — no delete work, no queue work, no splitter work. Those
are v0.16.0 and v0.17.0.

## Plan

Fix the confident wrong answers, and close the two auth holes.

**Non-goals.** A6's coverage rollup (a chapter's own concepts are excluded from its
coverage) — `test_mastery.py:92-96` asserts the current behaviour, so changing it is a
product decision, not a bug fix. S2 (the backend trusts `X-User-Db` unauthenticated) —
loopback-only publishing is the control and the deployment is single-tenant; to be
documented in ARCHITECTURE.md rather than coded around. Anything in v0.16.0/v0.17.0.

## Exit criteria

1. Read paths that turn an exception into empty data: **0** (was 11 — this cycle's share).
2. Backend handlers returning 200 on failure: **0** (was 3).
3. SQL sites keying a source-scoped table by a version id: **0** (was 4).
4. A custom course version with an edited outline serves the right concept cards, verified
   against a real converted book in the running app — not a fixture.
5. Backend suite shows no regression against the pre-cycle baseline; frontend typecheck clean.

## Build

Landed, with the reasoning:

| Finding | Change |
|---|---|
| A1 | `/api/engagement` passed the whole body as one positional arg to a 4-parameter function. Fixed the call and mapped the wire's `scope` onto `section_key`. |
| A2 | `reviews.py` now translates the span through `source_sections` before filtering concepts, matching `_chapter_snapshot` 100 lines above — which already did it, with a comment saying why. Typed rows keep the untranslated span, because skeleton/chapter cards genuinely follow the version. |
| A3 | `skeleton._concepts_by_section`, `generate_orient` and `eval_gate._sample_concepts` read through `concept_filter` — the one place the inheritance decision lives — and `_concepts_by_section` re-keys onto the version's outline via `version_sections_by_source`. |
| A4 | `elements._figures_by_section` and `fetch_elements` do the same. Figures are book-scoped on the same two columns as concepts, so the rule is identical. `fetch_elements` also re-keys before its scope filter, which was comparing a version scope against book keys. |
| A5 | `mastery`'s two loaders raise instead of returning `{}`; `compute_mastery` turns that into the error envelope the route already knows how to 503. |
| A9 | A slug scope's level is the 99 sentinel, so a `<= 99` terminator fired on the very next block and collapsed the chapter to one. Those now run to the next recognisably structural block; numeric and chapter-marker scopes are untouched. |
| A10 | `scope.py` gained `_numeric_body`, which strips the `~n` dedup suffix `outline._dedup_key` mints — so `toc:1.2~2` is finally inside `toc:1`, agreeing with `chapters._CHAPTER_OF`, which always did. |
| A11 | Cadence floors to UTC midnight and reaches back six days. The rolling 604800-second window spanned eight calendar days, rendering as "8/7 days this week". |
| E3/E4 | The three `progress_routes` handlers return `JSONResponse` with a status. `reviewDue` is `number \| null` end to end, and a failed debt read renders "—" rather than "Caught up". |
| E2 | `use-course-data` drops the outgoing course's numbers on switch and checks every response against the current doc before applying it, so course B can no longer render course A's coverage. |
| S1 | The middleware matcher's static-asset lookahead is anchored on the whole pathname, so `/api/**.map` skipped auth entirely. `/api/:path*` is now matched unconditionally. |
| S1b | `getUserDbName()` failed *open* to the primary tenant when there was no session. The dev fallback now has to be asked for by name (`LEARN_ALLOW_ANON_DB=1`). |
| S3 | `audiobook` path helpers go through `_doc_dir`, which strips the id to the safe charset and refuses if nothing is left — `os.path.join` discards everything before an absolute segment, so `?doc=/var/lib/secrets` escaped `AUDIO_DIR` entirely. |
| S4 | The login `from` parameter must be a same-origin path. |

Decision worth recording: `concept_filter` is used for `raw_elements` as well as
`ext_concepts`. Its name says "concept", but its body is generic over any book-scoped table
with `doc_id` + `section_key`, and duplicating the unmapped-version fallback would put the
same decision in two places — which is the failure this seam exists to prevent. If the name
grates, rename it; do not fork it.

## Test

- **Backend suite** (`pytest tests -q` in `compose-learn:latest`): 127 passed, 2 failed,
  8 errors. Byte-identical to the pre-cycle baseline, so **no regressions**.
  - The 8 errors are the `_pg` integration tests, which need a live Postgres DSN.
  - The 2 failures **pre-date this cycle**. Verified by running the same file against a
    pristine `git archive HEAD` extraction: `test_toc_controller.py` fails identically
    there. The code emits route `derived-numbering` while the tests still expect
    `derived-headings` — fallout from `bcb89f7 feat(toc): read a document's own heading
    numbering`, which shipped red. **Not fixed here; it needs a decision about which of
    the two is the intended contract.**
- **Hub contract** (`scripts/check_hubs.py`): holds — facades documented, no deep,
  private or upward cross-package imports, despite the new `elements → blocks` and
  `eval_gate → content` edges.
- **Frontend typecheck** (`tsc --noEmit`): clean.
- **Scope logic, executed** in the container against the real functions:
  `is_ancestor_section_key("toc:1", "toc:1.2~2")` → True (was False), `toc:1` vs `toc:11.2`
  → still False (no false prefix match); a slug scope spans its three blocks and stops at
  the next chapter; a numeric scope's span is unchanged.
- **Cadence window, executed**: 7 distinct UTC days for a mid-afternoon `now` (was 8).
- **Path traversal, executed**: `?doc=/var/lib/secrets` no longer escapes `AUDIO_DIR`,
  `../../..` is refused, a real uuid is unchanged.
