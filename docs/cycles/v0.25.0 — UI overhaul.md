# v0.25.0 — UI overhaul

Sub-cycle plan under [[0.) Development Protocol 1.0]]
Opened 2026-11-03

Addresses **Make learning more efficient**

> Each of fidelity, retention, competency and engagement carries evidence from one real book I studied end to end — not a demo corpus, and not the same book for all four

## Problem

The content is good and the interface is not. The human's words: "buggy, clunky, and not well
fleshed out." Diagnosis from the code on 2026-11-03: six overlapping study tools across 17 routes
with no single daily path; 43 surface files fetching on their own, 27 of them swallowing errors
(`catch(() => undefined)`), so a failed request shows as a blank panel; three visual systems
(`globals.css` tokens, the shadcn kit, the study theme only exam packs use); ten components of
450–900 lines mixing fetching, state and layout; no frontend tests. At stake: the PCAP exam on
2026-11-28 is studied in this app, so a UI that hides failures costs study time.

## Appetite

One working day of agent time, run as a workflow of about 10–12 agents (human's choice: medium).

## Plan

Human decisions (2026-11-03): daily use is Reading, Exam packs, Review queue, Concepts and
skeleton. Delete the old practice session and old exam mode; their data stays in the database.
Ship by tagging and deploying to prod. UI choices delegated to the agent ("I trust your decision
making on UI choices"). Open this cycle although 'Competency' holds the focus.

1. **Map** — four read-only agents: routes and navigation, data and errors, visual system,
   study-tool overlap. Output: an inventory.
2. **Spec** — the agent writes `docs/ui-spec.md`: the route list, the daily path, one theme, the
   component set and the data-layer contract.
3. **Foundation** — one agent: shared data hook with visible loading/error/empty/retry, the
   theme as the base for every page, the shared page/list/state components, the deletions.
4. **Migrate** — one agent per surface in its own worktree, using only the foundation.
5. **Verify** — a real browser on every route of the prod build: console errors, failed requests,
   blank panels, screenshots. Then tag, deploy, tick.

**Non-goals.** No backend behaviour changes beyond deleting routes only the removed tools use. No
new study features. No change of framework. No change to fleet.css (the study block stays a byte
copy). No database migration.

## Exit criteria

- Opening the app leads to one obvious daily path; every remaining route is reachable from nav.
- The practice session and old exam mode routes are gone; nothing links to them.
- A failed API request shows a visible error with retry on every surface (checked by blocking the
  API in the browser), not a blank panel.
- One visual system: every page uses the same tokens and kit; `fleet-ui/check.sh` is clean.
- `next build` and `tsc` pass; the browser sweep of every route shows no console errors.
- The human's study flow works on prod: open PE2 → Exam packs → start a sitting → answer → results.
