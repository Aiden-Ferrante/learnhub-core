# v0.25.0 — UI overhaul

Sub-cycle plan under [[0.) Development Protocol 1.0]]
Opened 2026-11-03

Addresses **Make learning more efficient**

> Each of fidelity, retention, competency and engagement carries evidence from one real book I studied end to end — not a demo corpus, and not the same book for all four

## Problem

The content is good and the interface is not. The human's words: "buggy, clunky, and not well
fleshed out." Diagnosis from the code on 2026-11-03: six overlapping study tools across 17 routes
with no single daily path; 43 surface files fetching on their own, 27 of them swallowing errors
(`catch(() => undefined)`), so a failed request shows as a blank panel; three visual systems
(`globals.css` tokens, the shadcn kit, the study theme only exam packs use); ten components of
450–900 lines mixing fetching, state and layout; no frontend tests. At stake: the PCAP exam on
2026-11-28 is studied in this app, so a UI that hides failures costs study time.

## Appetite

One working day of agent time, run as a workflow of about 10–12 agents (human's choice: medium).

## Plan

Human decisions (2026-11-03): daily use is Reading, Exam packs, Review queue, Concepts and
skeleton. Delete the old practice session and old exam mode; their data stays in the database.
Ship by tagging and deploying to prod. UI choices delegated to the agent ("I trust your decision
making on UI choices"). Open this cycle although 'Competency' holds the focus.

1. **Map** — four read-only agents: routes and navigation, data and errors, visual system,
   study-tool overlap. Output: an inventory.
2. **Spec** — the agent writes `docs/ui-spec.md`: the route list, the daily path, one theme, the
   component set and the data-layer contract.
3. **Foundation** — one agent: shared data hook with visible loading/error/empty/retry, the
   theme as the base for every page, the shared page/list/state components, the deletions.
4. **Migrate** — one agent per surface in its own worktree, using only the foundation.
5. **Verify** — a real browser on every route of the prod build: console errors, failed requests,
   blank panels, screenshots. Then tag, deploy, tick.

**Non-goals.** No backend behaviour changes beyond deleting routes only the removed tools use. No
new study features. No change of framework. No change to fleet.css (the study block stays a byte
copy). No database migration.

## Exit criteria

- Opening the app leads to one obvious daily path; every remaining route is reachable from nav.
- The practice session and old exam mode routes are gone; nothing links to them.
- A failed API request shows a visible error with retry on every surface (checked by blocking the
  API in the browser), not a blank panel.
- One visual system: every page uses the same tokens and kit; `fleet-ui/check.sh` is clean.
- `next build` and `tsc` pass; the browser sweep of every route shows no console errors.
- The human's study flow works on prod: open PE2 → Exam packs → start a sitting → answer → results.

## Build

Run as two workflows, 12 agents in total: map (4 read-only auditors, producing `docs/ui-inventory.md`),
then build (1 foundation, 5 surface migrators each in its own worktree, 1 integrator, 1
adversarial auditor). The agent wrote the spec (`docs/ui-spec.md`), because the human delegated UI
choices.

Decisions taken where the spec was silent:
- The course-wide review serves due cards only and introduces no new concepts. Debt and the
  calendar also stop counting the legacy `figure` type, which no runner serves.
- `pnpm-lock.yaml` is gitignored in this repo, so the dependency is pinned in package.json only.
  The Docker build resolves it.
- `frontend/.gitignore`'s bare `data/` was anchored to `/data/` so that `src/kit/data` could be
  committed.
- The header order is now brand, nav, breadcrumbs, so the brand never wraps (found in the browser).
- The study-bar sticky fix went upstream: fleet-ui 81574e4, re-copied byte for byte.

**ADR seeds.**
- Due counts for versioned courses are attributed to the source book's id, not the version's.
- `--primary-foreground` (zinc-950) differs from `--fleet-on-accent` (zinc-50).
- There is no ESLint config at all, so `next lint` cannot run.
- A temporary verifier login on prod was refused by the permission layer. Browser verification
  ran in the human's own signed-in Chrome instead.

## Test

Static: `tsc --noEmit` exit 0 (the old fleet-apps.tsx error is fixed); `next build` passes and has
no /practice route; pytest reported 230 passed, 30 skipped, 1 xfailed (8 new tests for the course
scope and the debt filter); `fleet-ui/check.sh` is clean.

Prod (:3001, images rebuilt from ui-overhaul), in the human's Chrome, 2026-11-03:
- **Library:** the Today panel shows 4 lines ("Review 2", "Review 9", "Continue Python Essentials
  1: Full book test", "Continue Python Essentials 2: Full book test"). The Plan badge shows 11,
  which equals 2 + 9.
- **PE2 course routes:** home, review ("Nothing due right now", consistent with no badge on PE2),
  chapter, read, concepts (653), skeleton, and the packs today/learn/exam tabs all render with no
  console errors and no failed /api requests. `/practice` returns 404.
- **Exam flow (PE1 Operators pack):** Start the clock, answer Q1, then answer Q2 with POSTs forced
  to fail. The page shows "Not saved (1 answer) · Couldn't reach the server · Retry". After the
  failure was removed, Retry cleared it. Submit asks "10 unanswered. Submit now?", and confirming
  it shows Results at 8% (1 of 12), "Provisional: 2 written still to mark", per chapter and per
  skill.
- **Miss:** pack pages wrapped "Learn Hub" onto two lines and truncated the breadcrumbs. Fixed
  (nav before breadcrumbs, no-wrap), redeployed and rechecked.
- **Not measured:** frame timing. The automation window throttles requestAnimationFrame to about
  2 s on every page, Upload included, so performance readings there mean nothing.
