# v0.26.0 — Questions you can check

Sub-cycle plan under [[0.) Development Protocol 1.0]]
Opened 2026-11-09

Addresses **Make learning more efficient**

> Each of fidelity, retention, competency and engagement carries evidence from one real book I studied end to end — not a demo corpus, and not the same book for all four

## Problem

The exam packs shipped in v0.24.0 hold questions a learner cannot check or should not see.
Read-only count on prod, 2026-11-09 (3 packs, 1,165 items):

- **130 Learn book problems have no answer.** The book prints none and nothing ran the code.
- **89 authored items point at the book, not the subject**: "fits the textbook", "what does the
  text say". This failure was named in the aborted v0.19.0 retro and never fixed.
- **Re-running one failed chapter overwrites the pack receipt** with that run's totals (PE2 was
  patched by hand on 11/02).
- **The sandbox's process limit never applied in prod.** The learn container runs as root, and
  RLIMIT_NPROC does not bind uid 0.

Opened although 'Competency' holds the focus. On 2026-11-09 the human set a `/goal` to
implement the five-area improvement list "while making full use of the PBTR cycles". That is
the go-ahead for this cycle and the four after it.

## Appetite

One session of agent time.

## Plan

1. `answers.py`: take the program out of a book problem (its `code`, else the block after the
   question line), run it in the sandbox, and store its stdout or `Raises X` as
   `computedAnswer`. Refuse to guess: blanks, `input()`, figures, flattened layout and names
   defined elsewhere stay self-marked.
2. Furniture: a regex check in `author_unit` drops an authored item that references its source,
   with the reason on the receipt. The author's RULES forbid it in every prompt.
3. Receipt: `pack_totals` sums every stored chapter receipt, and `build_pack` ends in
   `finalize_pack`.
4. Sandbox: the child drops to `nobody` when the service is root.
5. `scripts/repair_pack_items.py` brings the existing packs up to 1–3 (UPDATE only, dry-run
   default).

**Non-goals.** Re-extracting book problems whose code the converter flattened or lost. That is
the converter's bug and needs a reconversion. Exam MCQs that are not book problems (their keys
are model-written and judged). A container user change (Dockerfile), since dropping in the
child covers the limit.

## Exit criteria

- Every Learn book problem whose program runs as printed shows its real output on :3001.
- No authored item in prod fails the furniture check, except any the rewrite could not fix,
  which are listed here by key.
- Every pack's receipt equals the sum of its chapters.
- In the running learn container, a fork as the sandbox user is refused.

## Review

**What did the plan miss?** How much of the "no answer" problem lives in the converter. I
estimated ~95 "what's the output" questions. 34 were runnable, and 66 had their code lost or
flattened before any of this code saw them. Reading the real card also showed a bug the
numbers could not: markdown flattened code that was stored correctly. Both were found by
looking at output, not counts.

**What did the agent need that the prompt did not give?** That the host has no
`LEARN_PRACTICE_MODEL`. The first rewrite sample ran on the local default model and wrote a
stem with no question. Scripts that call the author should use the deployed config.

**What did I learn?** A check that rewrites content needs its own false-positive pass before
`--apply`. Two of the 89 "violations" were the check being wrong, and the rewrite's
self-validation (it must pass the check) is what surfaced them, by refusing.

Decision: ship.
